# 2026-07-30 修复文件审查两个 Bug：查看原文方块 + 流式输出 UI 缺失

## 修改内容

### Bug 1: 查看原文显示方块 → 改为 HTML 预览
**根因**：预览接口 `/api/app02/preview/{file_id}` 通过 LibreOffice 将 docx 转 PDF 后返回，但服务器缺少中文字体，PDF 中文全部显示为方块（tofu）。

**修复**：
- `backend/app/services/doc_converter.py`：新增 `convert_docx_to_html()` 纯 Python 函数，使用 `python-docx` 提取段落/表格/格式，直接生成 HTML。不依赖 LibreOffice/Word COM，浏览器原生渲染中文。外层加 try-catch 防止异常 500。
- `backend/app/routers/app02.py`：预览接口改为调用 `convert_docx_to_html()`，返回 `text/html` 而非 `application/pdf`。

### Bug 2: 流式输出 UI 不显示 AI 分析过程 → 多模型思考过程支持
**根因**：① `streamingTexts` 未在 UI 渲染 ② 后端只检查 `reasoning_content`（DeepSeek 专属），其他模型的思考字段（`thinking`/`reasoning`）被忽略。

**修复**：
- `backend/app/services/ai_reviewer_app02.py`：`_call_api_stream` 中同时检查 `reasoning_content`、`thinking`、`reasoning` 三个字段，任一有值即作为思考过程推送。
- `frontend/src/apps/app02/index.tsx`：
  - 解构新增 `streamingTexts` 字段
  - 流式面板分层展示：**思考过程为主**（灰色背景，始终展开），**分析结果为辅**（有思考过程时默认折叠，无思考过程时自动展开兜底）
  - 新增排队/等待状态的加载动画提示（"等待 AI 响应..."）

### Bug 1 补充: 500 错误修复
- `convert_docx_to_html` 外层加 try-catch，段落/表格迭代异常时返回 None 而非 500。
