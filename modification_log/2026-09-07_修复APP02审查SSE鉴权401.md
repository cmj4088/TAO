# 2026-09-07 修复 APP02 文件审查 AI 审查"一直加载"（SSE 401）

## 修改内容

### 1. 问题定位（智谱 API 排查引出）
- 用户反馈"使用智谱 API 无法正常使用，审查过程一直加载"
- 排查结论：智谱 API 与配置**均正常**——老师服务器（10.50.150.176:8006）调用 `llm-test` 1.1 秒连通（glm-4-plus），APP01 端到端复现 8.5 秒完整跑完
- 根因：v2.0.x 加账号系统时给 APP02 SSE 接口（`backend/app/routers/app02.py:384`）加了 `Depends(get_current_user)` 鉴权，但前端 `useAiReviewStream.ts` 用原生 `EventSource` 连接——**EventSource 无法携带 Authorization 头** → 后端永远 401；且 `es.onerror` 不处理该情况 → 界面无限"加载中"
- APP01 监考分配审查不受影响：其 SSE 接口（`app01.py:346`）无鉴权依赖
- 附带发现：APP01 审查后端只读管理员全局 LLM 配置（`routers/app01.py:337` 不传用户配置），用户级 LLM 配置仅 APP02 使用

### 2. 前端修复（方案：fetch 流式读取，前后端鉴权模型不动）
- `frontend/src/apps/app02/hooks/useAiReviewStream.ts`：整体重写
  - `EventSource` → `fetch` + `ReadableStream` 手动解析 SSE 帧，携带 `Authorization: Bearer` 头
  - 新增 `connectionError` 状态：401 提示"登录已过期"、非 200 提示状态码、断流提示"连接中断"，不再无限转圈
- `frontend/src/apps/app02/index.tsx`：接收 `connectionError`，toast 报错并结束 `aiReviewing` 加载状态

### 3. 重新打包
- `npm run package` 重新生成 `前端/教务办智能体 Setup 2.0.1.exe`（约 83.7MB，2026-09-07 17:54）
- 注：electron-builder 从 GitHub 下载工具超时，需加 `ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/` 镜像环境变量
- 验证：app.asar 中含新代码（`登录已过期`/`getReader()`），无 APP02 EventSource 残留（APP01 的 1 处为预期保留）
