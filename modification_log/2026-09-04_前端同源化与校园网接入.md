# 2026-09-04 前端同源化改造 + 副机接入校园网 + Electron 重打包

## 修改内容

### 1. 前端 API 同源化（根治 IP 写死问题）
- `frontend/src/api/client.ts` 第 4 行：`VITE_API_BASE` 的兜底判断从 `||` 改为 `??`（空字符串env生效为同源请求，不再误回落到 localhost）
- `frontend/.env.web`（新增）：`VITE_API_BASE=`（空），供 `vite build --mode web` 使用
- 效果：网页版产物**不写死任何后端 IP**，API 请求走同源 `/api`，由 nginx 反代到容器 8002。副机换网络/换 IP **无需重新打包网页版**

### 2. nginx 反代（副机）
- `/etc/nginx/sites-available/tao-frontend` 更新为 v2：新增 `location /api/` 反代 `127.0.0.1:8002`，含 SSE 流式支持（`proxy_buffering off`、`proxy_read_timeout 3600s`）

### 3. 副机接入校园网
- 根因：`/etc/network/interfaces` 残留僵尸静态 IP（10.220.109.93）导致 eth0 被 NM 视为 unmanaged
- 修复：清除静态段（备份 `interfaces.bak-20260904`），重启 NetworkManager，`nmcli con up "Wired connection 1"`（DHCP）
- 结果：eth0 获得 `10.220.109.114/22`，出网正常（无需 Web 认证）
- **限制**：实测校园网跨 /22 网段客户端隔离——主机（10.220.123.0/22）无法直连副机 80/8080。跨网段访问需 Tailscale 组网

### 4. Electron 安装包重打包
- `frontend/.env.production`：`VITE_API_BASE` 从 `http://10.220.109.93:8002`（僵尸 IP）→ `http://10.220.109.114:8002`
- `npm run package` 重新生成 `前端/教务办智能体 Setup 2.0.1.exe`（旧包写死僵尸 IP 导致"未连接到服务器"）
- 注意：Electron 版（file:// 协议）无法同源，必须写绝对 IP；校园网 IP 若 DHCP 变化需重打包
