## 数据库设计

| 表 | 关键字段 | 说明 |
|----|----------|------|
| `settings` | key(unique) / value / updated_at | 键值配置，敏感值 AES 加密 |
| `roles` | id / name / description | `admin`、`teacher` |
| `permissions` | id / resource / action | `user:read`、`user:write`、`settings:read`、`settings:write`、`stats:read`、`review:use` |
| `role_permissions` | role_id / permission_id | admin 全量；teacher 仅 `review:use` |
| `users` | id / email(unique) / password_hash / display_name / role_id | |
| `sessions` | id / user_id / token_hash / expires_at / revoked_at | 支持撤销 |
| `user_llm_configs` | user_id(unique) / llm_url / llm_key_encrypted / llm_model | 用户级 LLM 配置 |
| `verify_codes` | email / code / expires_at / used | 注册邮箱验证码 |
| `llm_usage` | user_id(可空) / model / prompt_tokens / completion_tokens / total_tokens / created_at | `user_id IS NULL` = 系统级（APP01） |

**系统级预置配置**（`settings` 表）

| key | 默认值 | 加密 |
|-----|--------|------|
| `llm_key` | 内置 Ark Key | ✅ |
| `llm_url` | `https://ark.cn-beijing.volces.com/api/v3/chat/completions` | ❌ |
| `llm_model` | `deepseek-v4-pro-260425` | ❌ |
| `app02_ai_concurrency` | `1`（范围 1–10） | ❌ |

**迁移与容灾**
- 建表/改表一律走 **Alembic**（`alembic/versions/`），启动时 `upgrade head` 自动执行。
- 存量库（有业务表但无 `alembic_version`）自动 `stamp 0001_initial` 接管。
- 每次迁移前 `VACUUM INTO` 自动备份（`data/backups/`，滚动保留 10 份）；迁移失败自动回滚并拒绝启动。
- 跨进程启动锁（`fcntl`/`msvcrt`）串行化多 worker 的 `init_db`。
- 管理员可导出/恢复全库（`/api/admin/backup/*`），恢复用 SQLite backup API 避免 Windows 文件占用。

## 前端设计

### 路由

| 路径 | 组件 | 守卫 |
|------|------|------|
| `/` | `RootRedirect` | 按登录态分流 |
| `/login` | `LoginPage` | — |
| `/register` | `RegisterPage` | — |
| `/home` | `ConsoleLayout` + `HomePage` | `AuthGuard` |
| `/app/*` | `ConsoleLayout` + `App01`/`App02` | `AuthGuard` |
| `/settings` | `SettingsPage` | `AuthGuard` |
| `/admin` | `AdminPage` | `AuthGuard requiredPermission="user:read"` |

### 组件与状态

```
App
├── ThemeProvider（明暗主题）
├── ConnectionBanner（后端不可达红色横幅）
├── UpdateNotification（Electron 更新）
├── BrowserRouter
│   └── ConsoleLayout（可折叠侧栏 / 顶栏 / 内容区）
│       ├── 首页 HomePage：应用卡片 + 当前模型名 + AI 用量卡（点击跳设置）
│       ├── App01（hidden 切换，始终挂载）
│       └── App02（hidden 切换，始终挂载）
└── Toaster（sonner）
```

| Store | 职责 |
|-------|------|
| `appStore` | 子应用注册表 + 当前激活应用 |
| `authStore` | 用户信息、登录态、`hasPermission()` |
| `settingsStore` | APP02 AI 并发数 |
| `themeStore` | 明暗主题 |

**关键设计**
1. **子应用始终挂载**：`display: none/block` 切换，保证 SSE 与后台任务不中断。
2. **token 统一存取**：`tokenStore.ts` 决定是否落 `localStorage`（"记住我"），刷新 token 不越权持久化。
3. **401 自动续期**：响应拦截器刷新并重放；并发请求排队等同一次刷新。
4. **SSE 两种实现**：APP02 用 `fetch` + `ReadableStream`（可带 `Authorization`）；APP01 仍用 `EventSource`（不带鉴权）。
5. **UI 体系统一**：Tailwind + shadcn/ui（Radix）+ lucide 图标（Ant Design 已移除）。

## 核心业务逻辑

### APP01 — 监考分配（`services/invigilator.py`）

**流程**
1. **总量校验**：考试场次 × 2 与教师目标总场次比对。
2. **确定性贪心（最多 20 次重试）**：每次换随机种子产生不同时段排序，逐时段三阶段：
   - 阶段 1 自己班优先 → 阶段 2 同组搭档 → 阶段 3 按剩余场次填坑 → 兜底从池外补位
3. **审查校验**：P1 严重（同时段重复、自己班未优先）/ P2 场次偏差 / P3 分组不一致
4. **AI 兜底**：20 次贪心全失败才调用 AI 分配

**表格约定**
- 考试安排表：第 3 行起为数据；第 6 列教学班级名、第 7 列班级名、第 9 列任课教师（`编号/姓名, 编号/姓名`）、第 10 列考试时间、第 11 列考试地点；导出填第 13 列（监考1）、第 15 列（监考2）。
- 通讯录：A 岗位 / B 姓名 / C 安排场次 / D 分组（区分大小写，空=无分组）。

**交互**：拖拽互换/替换、撤销栈、分级校验面板、AI 审查弹窗（SSE）、导出 Excel。

### APP01 — AI 审查（`services/ai_reviewer_app01.py`）

SSE 事件：`reasoning`（思考）、`token`（流式片段）、`done`（findings + summary）、`error`。
> 使用**管理员全局 LLM 配置**；`user_id` 为 NULL 记入系统级用量。

### APP02 — 文件审查

**三步审查**
1. **格式检查**（`doc_reviewer.py`）：从模板提取字体/字号作为合格标准，偏离即标记；文档字体种类 > 5 判不合格。
2. **课时计算检查**：周数 × 周学时 = 总学时 的逐行验算。
3. **课时一致性检查**：进度表逐行学时之和与汇总表声称总学时比对。

**.doc 兼容**：Word COM（Windows）或 LibreOffice（Docker 镜像内置）转 `.docx` 再处理。

**AI 审查 5 条规则**：学校名称错误（error）/ 教师信息不匹配（error）/ 错别字（warning）/ 课时验算（error）/ 格式问题（warning）。

**Python 后处理补丁**（确定性兜底，不依赖模型）
- 学校名：`深圳信息职业技术学院` → `深圳信息职业技术大学`
- 课时验算（TP 模板封面+进度表；CS/EM 模板内容分配表）
- 教师姓名一致性跨位置比对
- 已知错别字模式匹配

**并发控制**：`asyncio.Semaphore` + `app02_ai_concurrency`（1–10，默认 1）。

**输出**：通过绿 / 不通过红；单文件详情预览 + 口语化批注 + 一键复制；批量汇总表（文件名/老师/教师编号/错误类型/错误位置/问题描述）；导出 Excel。

### 认证与权限（`m1_auth/`）

- **注册**：邮箱验证码 → 建 `teacher` 账号。
- **登录**：`bcrypt` 校验 → 签发 JWT access + refresh；`sessions` 存 token 哈希。
- **会话**：登出/改密/重置密码撤销会话；access 过期由前端自动 refresh。
- **权限**：`require_permission("resource:action")` 依赖；前端 `AuthGuard requiredPermission`。
- **默认管理员**：`admin@tao.local`，随机初始密码写入 `data/admin_init.txt`。

### AI 用量统计（`routers/stats.py` + `services/llm_usage.py`）

每次 LLM 调用写 `llm_usage`（user_id 为空 = 系统级）。接口按 UTC+8 给出：累计、今日、按模型分布、近 7 天趋势，并区分 `me`（本人）与 `system`（APP01 等系统级）。

## 部署架构

### 后端（Docker）

```yaml
services:
  backend:
    image: ghcr.io/cmj4088/tao-backend:latest
    ports: ["8002:8002"]
    volumes: ["./data:/app/data"]
    environment: [ENCRYPTION_KEY=change-me-to-a-random-secret-string]
    restart: unless-stopped
```

- 镜像：`python:3.12-slim` + LibreOffice + gunicorn 4×uvicorn worker。
- 离线环境可用 `Dockerfile.offline`（wheels 离线安装）。
- 更新：`bash update.sh`（拉新镜像 → 重启；启动时自动迁移 + 自动备份）。

### 前端

| 形态 | 构建 | 分发 |
|------|------|------|
| 桌面版 | `npm run package` → `前端/教务办智能体 Setup X.Y.Z.exe` | electron-updater 走 GitHub Release 自动提示更新 |
| 网页版 | `npx vite build --mode web` → `dist/` | 上传到 nginx 站点，`location /api/` 反代 8002（需 `proxy_buffering off` 支持 SSE） |

### CI/CD

| 工作流 | 触发 | 动作 |
|--------|------|------|
| `backend-docker.yml` | push `backend/**`（main / combined-test） | 构建推送 `ghcr.io/cmj4088/tao-backend` |
| `frontend-release.yml` | push `frontend/**` | windows-latest 构建安装包，上传 artifact（保留 30 天） |

## 已知问题

> 2026-10-14 已处理：`.git` 回收 1.88GB 不可达对象；清理重复副本与旧安装包；根 `package.json` 副本、`update-server/`（已废弃的本地更新分发）删除；两份过期文档重写至 2.0.2。

1. **APP01 全部端点无鉴权**；其 SSE 用 `EventSource` 无法带 `Authorization`，加鉴权需同步改前端为 fetch 流。
2. **`GET /api/app02/ai-review/progress/{task_id}` 无鉴权**，task 字典全局共享。
3. **APP01 AI 审查只读管理员全局 LLM 配置**，用户级配置仅 APP02 生效。
4. **断点续作未完全落地**：APP02 结果在后端内存，重启后端即丢失。
5. **`VersionBadge.tsx` 为死代码**（顶栏仅留占位注释），内含 `0.1.3` 兜底常量。
6. **`backend/data/admin_init.txt` 明文保存初始管理员密码**，登录后应立即改密。
7. **桌面版 IP 写死**：后端地址或校园网 DHCP 变化需重新打包。
