# 教务办·智能体 — 项目设计与需求（2026-07-09 更新）

## 项目概述

**项目名称**：教务办·智能体（TAO）
**当前版本**：0.1.3

## 核心业务逻辑

### App01 — 监考分配算法

**文件**：`backend/app/services/invigilator.py`

**算法流程**：
1. **总量校验**：检查考试场次×2是否等于教师总场次
2. **确定性贪心分配**（最多20次重试）：
   - 每次重试使用不同随机种子，产生不同的时段排序
   - 逐时段处理，三个阶段：
     - **阶段1**：自己班优先 — 任教老师优先监考自己班级
     - **阶段2**：分组搭档 — 同组老师尽量安排在同一考场
     - **阶段3**：填坑 — 剩余老师按剩余场次多少填充空位
     - **最终兜底**：从池子外补充未分配位置
3. **审查校验**：每次分配后检查冲突
   - P1 严重：同时段重复、自己班未优先
   - P2 场次偏差：实际场次≠目标场次
   - P3 分组不一致：同组老师时间段集合不同
4. **AI兜底**：20次贪心全部失败时，调用AI进行最终分配

**通讯录格式**（新版4列）：
- A列：岗位
- B列：姓名
- C列：安排场次（数字）
- D列：分组（区分大小写，空=无分组）

**考试安排表格式**：
- 第3行起为数据行
- 第6列：教学班级名称
- 第7列：班级名称
- 第9列：任课教师（格式：`编号/姓名, 编号/姓名`）
- 第10列：考试时间
- 第11列：考试地点
- 导出时填充第13列(监考1)和第15列(监考2)

### App01 — AI审查（SSE流式）

**文件**：`backend/app/services/ai_reviewer_app01.py`

通过SSE推送审查结果，事件类型：
- `reasoning`：AI思考过程
- `token`：流式输出的文本片段
- `done`：审查完成，返回findings列表+summary
- `error`：审查出错

### App02 — 文件审查

**文件**：`backend/app/services/ai_reviewer_app02.py` + `doc_reviewer.py` + `doc_converter.py`

**审查流程**：
1. **上传**：支持 `.doc` / `.docx` 文件，自动识别模板类型
2. **格式转换**：`.doc` 通过 Word COM 转 `.docx`
3. **格式审查**（`doc_reviewer.py`）：模板分类
4. **AI审查**（`ai_reviewer_app02.py`）：
   - 提取文档全部文本（段落+表格）
   - 构建包含5条规则的审查prompt
   - 流式调用AI（SSE），支持并发控制
5. **后处理补丁**（Python层面确定性检查）：
   - 学校名检查："深圳信息职业技术学院"→"深圳信息职业技术大学"
   - 课时验算：TP模板（封面+进度表）和CS/EM模板（内容分配表）
   - 教师姓名一致性：扫描所有出现位置对比
   - 已知错别字：29组常见错别字模式匹配

**AI审查5条规则**：
1. 学校名称错误（error）
2. 教师信息不匹配（error）
3. 错别字（warning）
4. 课时计算校验（error）— 逐行数学验算
5. 格式问题（warning）— 字体/字号/对齐

**审查模式**：
- 单文件：详细预览+错误批注
- 批量：汇总表格（文件名/老师/教师编号/错误类型/错误位置/问题描述）

**并发控制**：通过 `app02_ai_concurrency` 配置（1-10），使用 `asyncio.Semaphore` 控制

### 配置管理

**文件**：`backend/app/config.py` + `backend/app/crypto_utils.py`

**三级回退机制**：
1. 函数参数传入的值（优先级最高）
2. ConfigManager 从数据库读取
3. 代码中硬编码的默认值

**加密机制**：
- 算法：AES-256-CBC
- 密钥：由 `ENCRYPTION_KEY` 环境变量派生（Docker部署时设置）
- 敏感字段：`llm_key`
- 存储格式：`AES::<base64密文>`
- 兼容性：旧明文数据自动检测并迁移为加密存储
- 脱敏显示：`ark-00ec****b92c`（保留前14后5字符）

## 部署架构

### Docker 部署

```yaml
# docker-compose.yml
services:
  backend:
    image: ghcr.io/cmj4088/tao-backend:latest
    ports:
      - "8002:8002"
    volumes:
      - ./data:/app/data          # SQLite数据持久化
    environment:
      - ENCRYPTION_KEY=change-me  # AES加密密钥
    restart: unless-stopped
```

- 容器内运行：gunicorn + uvicorn worker（4 workers）
- 镜像仓库：GitHub Container Registry (ghcr.io)
- 更新方式：`bash update.sh`（手动拉取最新镜像）

### CI/CD

**GitHub Actions**：
- **backend-docker.yml**：推送 backend/ 变更时自动构建Docker镜像并推送到GHCR
- **frontend-release.yml**：推送 frontend/ 变更时自动构建Electron安装包

**触发分支**：`main`、`combined-test`

### 更新机制

- **后端**：手动运行 `update.sh`（docker compose pull + up）
- **前端**：Electron 主进程检测 GitHub Release 新版本 → UpdateNotification 弹窗提示
- **已移除**：Watchtower 自动更新（改为手动触发）
