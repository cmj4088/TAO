# services/invigilator.py — 监考分配核心算法

**文件路径**：`backend/app/services/invigilator.py`

**算法类型**：确定性贪心 + 20次随机重试 + AI兜底

**核心函数**：

- `allocate(exam_rows, teachers, skip_ai=False)`：核心分配入口
  1. 总量校验 → 20次贪心重试（每次随机化3种时段排序策略）
  2. 每次用 `_review` 评估，无严重错误(P1/P2)则直接返回
  3. 20次全失败 → AI兜底分配
  4. AI失败 → 返回最优贪心结果

- `_assign_all(...)`：一步完成分配
  - 3种时段排序策略随机选择（按考场数降序/升序/随机）
  - 阶段1：自己班优先（任教老师先坐自己的班）
  - 阶段2：分组搭档（同组教师坐同一考场）
  - 阶段3：填坑（剩余多的优先）
  - 阶段4：最终兜底（从池子外补充）

- `_select_pool(...)`：选择当前时段可用教师池子
  - 任教老师优先 → 同组连带 → 剩余多的补充 → 池子过大时移除非优先级

- `_review(...)`：审查分配结果
  - P1(严重)：同时段重复、自己班优先（任教老师未监考自己班且自己班有空位）
  - P2：场次匹配（实际 vs 目标）
  - P3：分组不一致（同组老师时间段集合不同）

- `_ai_allocate(...)`：AI兜底分配
  - 构建提示词（考试安排+教师信息+分组+约束）→ 调用AI → 解析JSON分配方案

- `validate(exam_rows, teachers)`：独立校验函数，供路由器调用

**AI调用**：使用 `urllib.request` 同步调用火山引擎Ark API，timeout=120秒
