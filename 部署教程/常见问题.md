# 常见问题

## 前端

### Q: 用户打开软件没有提示更新？

1. 检查 `latest.yml` 中的版本号是否比用户当前版本高
2. 检查 GitHub Releases 页面是否有对应的 release
3. 用户网络是否能访问 GitHub（国内可能被墙，需要代理）

### Q: 下载更新失败？

- 国内用户可能无法直接访问 GitHub Releases 下载文件
- 解决方案：考虑在国内 CDN 放一份安装包，或使用代理

### Q: 安装包太大怎么办？

当前 .exe 约 85MB，主要因为 Electron 自带 Chromium 内核。
- 无法显著减小，这是 Electron 应用的固有特性
- 可以考虑用 electron-builder 的增量更新功能（需要配置）

### Q: electron-builder 发布失败？

检查：
1. GitHub Token 权限是否包含 `repo` scope
2. `GH_TOKEN` secret 是否在仓库 Settings → Secrets 中配置
3. 仓库 Actions 权限：Settings → Actions → General → Workflow permissions → 勾选 "Read and write permissions"

## 后端

### Q: docker compose up 报错 "pull access denied"？

说明没有登录 GHCR 或者 token 过期了。重新登录：
```bash
echo "新TOKEN" | docker login ghcr.io -u cmj4088 --password-stdin
```

GHCR 的镜像默认是私有的，需要在 GitHub 上设置为公开：
1. 去 https://github.com/cmj4088/TAO/pkgs/container/tao-backend
2. 点击 "Package settings"
3. 在 "Danger Zone" 中点击 "Change visibility" → 改为 "Public"

### Q: watchtower 不自动更新？

1. 检查 watchtower 日志：`docker compose logs watchtower`
2. 确认 backend 容器有 `com.centurylinklabs.watchtower.enable=true` 标签
3. watchtower 默认 5 分钟检查一次，新镜像推送后需要等一会儿

### Q: 更新后数据丢了？

数据在 `./data` 目录下，只要 volume 挂载没删就不会丢。
如果确实丢了，检查 `docker-compose.yml` 中 `volumes` 配置是否正确。

### Q: 服务器重启后服务会自动启动吗？

会。`restart: unless-stopped` 保证 Docker 启动时自动启动容器。

## GitHub Actions

### Q: 构建失败怎么办？

去仓库的 Actions 标签页，点进失败的 workflow 查看日志。
常见原因：
- 依赖安装失败（网络问题，重试一般能过）
- 磁盘空间不足（Windows runner 偶尔会出现）
- Secret 没配置

### Q: 需要配置哪些 Secrets？

在仓库 Settings → Secrets and variables → Actions 中：

| Secret | 用途 | 必需 |
|--------|------|------|
| `GH_TOKEN` | electron-builder 发布 Release | 是（前端） |
| `GITHUB_TOKEN` | 推送到 GHCR | 自动提供，无需配置 |

> `GITHUB_TOKEN` 是 GitHub Actions 自动生成的，不需要手动配置。
> 但需要在 Settings → Actions → General → Workflow permissions 中勾选 "Read and write permissions"。
