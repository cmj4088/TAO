# 前端更新指南

## 工作原理

```
开发者推送代码 → GitHub Actions 自动构建 .exe → 发布到 GitHub Releases
                                                      │
                                                      ▼
                                          用户打开软件 → electron-updater
                                          自动检测 → 提示更新 → 下载安装
```

## 发布新版本（开发者操作）

### 1. 修改版本号

编辑 `frontend/package.json`，修改 `version` 字段：

```json
{
  "version": "0.2.0"
}
```

同时也修改 `backend/app/main.py` 中的版本号保持一致：

```python
VERSION = "0.2.0"
```

### 2. 提交代码并推送

```bash
git add .
git commit -m "chore: bump version to 0.2.0"
git push
```

### 3. 等 GitHub Actions 跑完

推送后 GitHub 会自动：
1. 编译 TypeScript + Vite 打包前端
2. 用 electron-builder 打包成 NSIS 安装程序（.exe）
3. 发布到 GitHub Releases 页面
4. 生成 `latest.yml` 更新清单

在仓库的 **Actions** 标签页可以查看构建进度。

### 4. 在 Releases 页面确认

去 `https://github.com/cmj4088/TAO/releases` 确认新版本已经出现。

## 用户端更新流程（自动）

用户打开软件后：
1. 自动检查 GitHub Releases 有没有新版本
2. 有新版本 → 弹窗提示"发现新版本 v0.2.0"
3. 用户点击"立即更新" → 下载进度条
4. 下载完成 → 提示"重启安装"
5. 重启后自动安装新版本

**用户不需要手动下载任何东西。**

## 版本策略

| 触发方式 | 发布类型 | 适用场景 |
|---------|---------|---------|
| push 到 main 分支 | beta 草稿版 | 内部测试 |
| 推送 v1.0.0 标签 | 正式稳定版 | 对外发布 |

### 发布正式版

```bash
git tag v1.0.0
git push origin v1.0.0
```

## 关键配置文件

- `frontend/package.json` → `build.publish` 配置 GitHub 仓库地址
- `frontend/electron-main/main.cjs` → `autoUpdater` 配置检查更新逻辑
- `frontend/src/components/UpdateNotification.tsx` → 更新提示 UI 组件

## electron-builder 发布配置说明

`package.json` 中的 `publish` 字段：
```json
"publish": {
  "provider": "github",   // 用 GitHub Releases 托管
  "owner": "cmj4088",     // GitHub 用户名
  "repo": "TAO"           // 仓库名
}
```

如果换仓库，改这里的 `owner` 和 `repo` 就行。
